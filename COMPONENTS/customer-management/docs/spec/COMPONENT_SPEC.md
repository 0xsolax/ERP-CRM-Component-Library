# customer-management 组件规范

## 业务对象

客户管理至少包含以下对象：

- 客户主档：客户编号、名称、归属业务员、跟进人、类型、层级、地区、官网、地址、备注。
- 联系人：姓名、邮箱、职位、生日、性别、电话、社交账号、名片/头像。
- 收货地址：收货人、电话、国家地区、省市县、详细地址。
- 标签：客户标签，用于打样客户、订单客户等分层。
- 跟进记录：主题、联系人、行动描述、附件、下次回访日期。

## 最小实现

最小可接入版本必须具备：

1. 客户列表、详情、新增、编辑、删除或停用。
2. 客户主档与报价/订单的 `customer_id` 引用。
3. 客户列表和客户下拉的数据权限过滤。
4. 客户联系人和收货地址至少一套可维护能力。
5. 客户导入/同步边界说明。

## 完整实现

完整 CRM 版本可增加：

- 多联系人、多电话、多社交账号、名片/头像。
- 多收货地址和地区树。
- 客户标签。
- 跟进记录和下次回访日期。
- 自动客户层级规则。
- 消费趋势、消费占比、近一年累计金额和最近下单时间。
- 客户独立仓、客户产品规格对照、VIP 客户。

## 数据权限

客户数据权限必须区分：

| 范围 | 含义 | qmy-java 证据 |
| :--- | :--- | :--- |
| 本人 | 当前用户是归属业务员或跟进人 | `belong_employee_id` / `follow_employee_id` 包含当前用户 |
| 部门 | 当前用户是部门负责人时包含部门成员 | `AuthenticationInterceptor` 将部门成员加入 `createUserIdList` |
| 全公司 | 用户数据权限为全部数据，或租户未开启该权限的数据范围过滤 | `SysUserDataPermission.isOrganizeData = 1` 或无数据权限配置 |
| 老板视角 | 业务上等同全局看数，需要角色和数据权限明确授权 | 未见独立老板接口，需在项目权限配置中实现 |

## 导入和同步边界

客户来源必须按项目确认：

- 手工录入：默认可做。
- Excel 导入：可选能力，需要重复客户合并规则。
- 平台接口同步：可选能力，需要平台 API 授权和字段映射。
- 爬虫采集：非默认能力，必须先确认授权、平台规则和数据安全。
- 管家婆同步：非默认能力，仅可作为特定项目集成参考。

## 不可直接复用点

- legacy `zhongsheng-AI` 客户 schema 与实体不一致。
- `qmy-java` 部分客户子资源接口权限注解被注释。
- `qmy-java` 建表 SQL 缺失，需要按实体和 Mapper 重新生成迁移。
- 前端依赖全局管理后台基座，不能把 customer 目录单独拷贝后直接运行。
