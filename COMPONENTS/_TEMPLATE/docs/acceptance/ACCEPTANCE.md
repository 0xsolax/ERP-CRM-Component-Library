# Acceptance Checklist

## 快照完整性

- [ ] `component.yaml` 已填写真实组件名、状态、依赖和入口。
- [ ] `README.md` 能说明组件用途、接入步骤和限制。
- [ ] `SOURCE_MAP.md` 保留所有关键 `RAW/...` 来源路径。
- [ ] `docs/source/` 已带出原始规范或说明文档。
- [ ] `docs/spec/` 已整理组件实现规范。
- [ ] `docs/contracts/` 已覆盖 API、数据、权限。

## 代码与数据

- [ ] `backend/` 只包含当前组件相关代码。
- [ ] `frontend/` 包含页面、API、路由或组件依赖说明。
- [ ] `db/` 包含表结构、种子或迁移说明。
- [ ] 缺失的后端、前端或数据模型已明确标记为待验证。

## 污染检查

- [ ] 不包含 `.git/`。
- [ ] 不包含 `.DS_Store`。
- [ ] 不包含 `target/`。
- [ ] 不包含 `node_modules/`。
- [ ] 不包含 `.env` 或本地密钥。
- [ ] 不包含 Token、数据库密码、OSS AccessKey 等敏感信息。

## 装配验收

- [ ] 能说明依赖哪些基础组件。
- [ ] 能说明接入顺序。
- [ ] 能说明最小可运行路径。
- [ ] 能说明主要异常和权限边界。
- [ ] 能说明不能直接复用的风险。
