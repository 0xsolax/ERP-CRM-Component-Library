# COMPONENT_SPEC｜quote-management

## 目标

沉淀报价管理的两类可复用形态：

- 基础报价 CRUD：客户、报价日期、有效期、总金额、状态、备注和报价明细。
- 复杂报价流：客户报价、SKU 报价、成本核算、采购/物流成本确认、历史报价参考、审核会签、总裁微信审核和转订单。

## 业务对象

| 对象 | 说明 |
| :--- | :--- |
| 报价主档 | 报价编号、客户、业务员、币种、税、汇率、收货地址、订单金额、成本、状态 |
| 报价 SKU | 产品、搭配、SKU、基础报价、最终报价、数量、体积、备注 |
| 报价包材 | 报价 SKU 关联的包材、附件、装箱数、包材数量、成本、尺寸 |
| 报价历史 | 报价操作记录、提交审核、成本确认、驳回、会签、总裁微信审核 |
| 历史报价参考 | 同 SKU/搭配的历史价格、客户趋势、均价、中位数、毛利率 |
| 转订单桥接 | 报价生成订单、订单明细和操作记录 |

## 状态流

| 状态 | 来源值 | 业务含义 |
| :--- | :--- | :--- |
| 暂存 | `0` | 报价未进入成本核算 |
| 计算成本中 | `1` | 已提交，等待采购/物流成本 |
| 计算成本完毕 | `2` | 成本确认完毕，等待审核 |
| 审核中 | `3` | 前端展示值，具体后端以会签状态组合判断 |
| 审核通过 | `4` | 财务与总裁会签均通过 |
| 总裁未审核，财务未审核 | `5` | 双方待审核 |
| 总裁审核通过，财务未审核 | `6` | 总裁已通过 |
| 总裁未审核，财务审核通过 | `7` | 财务已通过 |
| 总裁微信审核通过，财务未审核 | `8` | 销售上传微信审核凭证 |
| 审核驳回 | `-1` | 报价被驳回 |

## 成本口径

- 采购成本：包材、配件、零件聚合后的采购侧成本。
- 工艺成本：人工工序量、油漆工序量、产品面积和字典中的油漆单价共同计算。
- 配件成本：配件单价乘搭配配件数量，按单个 SKU 口径计算。
- 包材成本：包材成本除以装箱数后累加，形成单件包材成本。
- 物流成本：按报价体积、箱数、收货地址和物流确认结果进入报价主档。
- 总成本：采购成本、物流成本、配件/工艺等明细成本聚合，具体公式需按目标行业确认。

## 历史报价口径

- 历史报价按 `skuId + matchId` 检索。
- 本次报价保留报价单原币种。
- 平均报价和中位数统一按人民币计算，美元报价按报价快照汇率折算。
- 毛利率使用报价减 SKU 成本后除以报价，来源实现未对所有空值和 0 报价做完整防御，接入时需补边界。
- 跨客户趋势涉及客户敏感信息，应按角色或脱敏规则控制。

## 转订单规则

- 整单转订单：报价主档转订单，所有报价 SKU 和包材进入订单明细。
- 单 SKU 转订单：只转指定报价 SKU，并检查该报价是否全部 SKU 已转换。
- 合并转订单：多个报价 SKU 合并生成订单，要求客户与业务员一致，SKU 不能重复。
- 订单来源、交货日期、合同编号由转订单参数提供。
- 订单组件负责后续订单状态、发货、采购和同步能力。

## 接入原则

- 报价必须保存时点快照，不应读取产品实时价格覆盖历史报价。
- 所有客户、成本、毛利率、历史报价和审核凭证接口都需要后端数据范围控制。
- 基础 CRUD 与复杂流只能选择一种作为生产主模型，避免双表并行造成报价口径分裂。
